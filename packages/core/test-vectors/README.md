# Test vectors

Fixed inputs and expected outputs for the crypto format. Every consumer must pass the same vectors: the browser, the CLI, and the Worker (for the parts it validates).

A vector is a JSON file with the inputs (keys, plaintext, nonces) and the bytes that must come out, so anything that decrypts in one place decrypts in all of them. Add a vector whenever the format changes.

| File               | Covers                                                                                                                                                                                                                                                          | Checked in                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `fingerprint.json` | ADR 22 per-name fingerprints: HMAC-SHA256 under the group key over `fp\|<path>\|<NAME>\|<value>`, first 8 bytes in hex. Expected values were cross-checked with `openssl dgst -sha256 -mac HMAC`.                                                               | `packages/core/src/core.test.ts`, `apps/cli/src/commands/versions.test.ts`                       |
| `recovery.json`    | ADR 20 recovery phrase (32 bytes to 24 BIP-39 words with checksum) and the four fingerprint words (first 44 bits of SHA-256 of the SPKI). Expected words were cross-checked with an independent Python implementation (`hashlib`) using the official word list. | `packages/core/src/recovery.test.ts`, `apps/cli/src/commands/recovery.test.ts`                   |
| `backup-seal.json` | ADR 23 backup passphrase seal: `CFSSEAL1` header, PBKDF2-SHA256 (600000) to AES-256-GCM, header as AAD. Recomputed with Node's `crypto` module as an independent check.                                                                                         | `packages/core/src/backup-seal.test.ts`, `apps/cli/src/commands/backup.test.ts`                  |
| `envelope.json`    | ADR 2/10 envelope `v1.<iv>.<ciphertext>` (AES-256-GCM, AAD bound): open with the key and AAD, reject any other AAD. Expected envelopes were produced with Node's `crypto` module.                                                                               | `packages/core/src/vectors.test.ts` (Bun), `packages/core/browser-test/vectors.pw.ts` (Chromium) |
| `wrapped-key.json` | ADR 10 wrapped key: ephemeral ECDH P-256, HKDF-SHA256 with info `cfs-wrap-v1\|<epk>\|<recipient>`, AES-GCM. Opens with the recipient's PKCS8 and SPKI keys. Produced with Node's `crypto` module.                                                               | Bun and Chromium, as above                                                                       |
| `kit.json`         | ADR 15 access kit `cfskit1_` + base64url(JSON) with fields in a fixed order, and kits that must be rejected.                                                                                                                                                    | Bun and Chromium, as above                                                                       |
| `audit-chain.json` | ADR 6 hash chain: `b64u(SHA-256(prev + "\n" + canonical JSON))` from `genesis`, and a tampered row that must be found. Hashes computed with Node's `crypto` module and its own canonical JSON.                                                                  | Bun and Chromium, as above                                                                       |
| `secret.json`      | ADR 10 key hierarchy: member private key opens the group key, the group key opens the DEK, the DEK opens the values. Each AAD binds its layer.                                                                                                                  | Bun and Chromium, as above                                                                       |

The Bun runner (`src/vectors.test.ts`) and the Chromium runner (`browser-test/vectors.pw.ts`) share one set of checks (`browser-test/checks.ts`), so both runtimes run the same assertions on the same files. Run the browser one with `bun run test:browser` (Chromium from `bunx playwright install chromium`).

`login.json` contains a fixed Login envelope and fingerprints, plus all RFC 6238 Appendix B TOTP cases. The shared vector runner checks it in Bun and Chromium; the CLI suite checks the same file.
